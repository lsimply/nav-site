# 精选导航 · 数据管理

页面文件 `index.html` 只负责展示，所有站点都在 `sites.js` 里。增删改站点只改这个文件，不用动页面。

## 文件说明

| 文件 | 作用 | 是否上传到网站 |
|---|---|---|
| `index.html` | 导航页 | 是 |
| `sites.js` | 站点数据 | 是 |
| `sites.csv` | 当前数据的表格版，可导入 Excel、WPS、在线表格 | 可选（见下方“国内推荐方案”） |
| `admin.html` | 可视化管理页，在浏览器里编辑站点，生成新的 `sites.js` | **不要上传**，只在自己电脑上用 |

## 国内推荐方案：用管理页，不依赖任何境外服务

1. 双击打开本地的 `admin.html`（要和 `sites.js` 放在同一个目录）。
2. 增删改站点和分类，修改会自动保存为草稿。也可以先“导出 CSV”，在 Excel 或 WPS 里批量改，再“导入”。
3. 点“下载 sites.js”，用它覆盖网站里原来的 `sites.js`，重新上传即可。

管理页只在你本机运行，不联网，也不会改动线上网站。不上传 `admin.html`，别人就没有管理入口。

## 想让页面自动读取表格，国内怎么做

Google 表格在大陆通常打不开，页面读不到时会自动用 `sites.js` 的本地数据，不会出错。国内更稳的做法是把 CSV 放在自己网站上：

1. 在管理页点“导出 CSV”，得到 `sites.csv`。
2. 把 `sites.csv` 上传到网站，和 `index.html` 放在同一个目录。
3. 在 `sites.js` 里把 `window.SHEET_URL` 改成 `"sites.csv"`。

这样页面会先显示本地数据，再读 `sites.csv`，两者同源，不存在跨域问题，国内访问速度也和网站一样。以后只要覆盖这个 CSV 就能更新。

## 用 Cloudflare 让大陆也能读到 Google 表格

只给域名接上 Cloudflare 的 CDN 不够：页面读 Google 表格时，是访客的浏览器直接去连 `docs.google.com`，不经过你的域名，所以大陆访客照样连不上。要让 Cloudflare 的服务器替访客去读，需要一个 Worker：

1. 登录 Cloudflare → Workers & Pages → Create → Create Worker，名字随意，点 Deploy。
2. 点 Edit code，把 `cloudflare-worker.js` 的内容整个粘贴进去（表格 ID 已经填好，换表格时改文件顶部的 `SHEET_ID`），再点 Deploy。
3. 进入这个 Worker → Settings → Triggers → Add route，路由填 `你的域名/api/sheet`（域名必须已经接入 Cloudflare 并开启橙色云朵代理），Zone 选你的域名。
4. 浏览器访问 `https://你的域名/api/sheet`，能看到一段 CSV 文字就成功了。看到 502 说明表格没有设为“知道链接的任何人可查看”。
5. 在 `sites.js` 里把 `window.SHEET_URL` 改成 `"/api/sheet"`，重新上传。

之后在 Google 表格里改内容，最多 5 分钟后页面就会更新。

注意：
- 不要用 `xxx.workers.dev` 这种默认域名，在大陆经常打不开，一定要用自己的域名路由。
- 这个方式解决的是“读 Google 表格”，访客仍然要能打开你的网站。Cloudflare 免费线路在大陆有时较慢或不稳定，这是它本身的限制，页面读不到时会继续显示本地数据。
- Worker 免费套餐每天有 10 万次请求额度，个人导航站够用。

## 加载过程

- 先立即显示缓存或本地数据，再在后台同步在线表格，内容真的变了才更新，并有淡入过渡。
- 同步失败（比如网络不通）时页面不受影响，继续显示已有数据，顶部统计下方会有提示（“最新数据暂时读不到”）。
- 没有任何本地数据、只靠在线表格时，会先显示骨架占位，再显示内容。

## sites.js 结构

文件开头是 `window.SITES_DATA = `，后面是下面这样的数据，末尾有一个分号。

```js
window.SITES_DATA = {
  "updated": "2026-11-18",
  "categories": [
    { "id": "tools", "name": "效率工具", "note": "一句你的使用心得，可以留空" }
  ],
  "items": [
    {
      "c": "tools",
      "name": "站点名",
      "icon": "image",
      "url": "https://example.com",
      "desc": "一句话说明为什么好用",
      "tags": ["免费", "新增"],
      "pin": true
    }
  ]
};
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `c` | 是 | 分类 id，必须是 `categories` 里已有的 |
| `name` | 是 | 站点名 |
| `url` | 是 | 以 `https://` 开头，同一个网址不要重复 |
| `icon` | 否 | 两种写法：图标名（可选值见 `index.html` 里的 `ICONS`），或图片地址，比如 `"https://example.com/favicon.png"`、`"icons/chatgpt.svg"`（相对路径，图片放在同一目录下）。不写或图片加载失败时显示链接图标 |
| `desc` | 否 | 简介，建议 30 到 60 字，写“为什么好用” |
| `tags` | 否 | 标签。`新增` 显示蓝色，`热门` 显示橙色，出现 2 次以上的标签会自动进入筛选栏 |
| `pin` | 否 | 设为 `true` 时可进入首页“热门推荐”（带 `热门` 标签的站点优先） |

## 日常操作

- **加站点**：在 `items` 里复制一行，改内容，注意逗号。
- **改分类顺序**：调整 `categories` 的顺序，页面和左侧栏同步变化。
- **新增标记**：新站点加标签 `新增`，一个月后去掉。
- **每次修改后**：把 `updated` 改成当天日期。

## 用在线表格管理（可选）

不想改代码文件时，可以把站点放进在线表格，页面会自动读取。

1. 把 `sites.csv` 导入在线表格（Google 表格：文件 → 导入 → 上传）。第一行是表头，保持不变。
2. 在表格里“发布到网络”，格式选 **CSV**，复制生成的链接。Google 表格的路径是：文件 → 共享 → 发布到网络。
3. 打开 `sites.js`，把链接填进第一行的 `window.SHEET_URL = ""` 引号里。
4. 以后在表格里增删改，刷新页面就能看到，不用再动文件。

表格列：

| 列 | 说明 |
|---|---|
| 分类 | 必填，同名的行归为一个分类，分类顺序按第一次出现的顺序 |
| 站点 / 网址 | 必填，网址要以 `https://` 开头 |
| 图标 | 可选，图标名或图片地址 |
| 简介 | 可选，一句话说明为什么好用 |
| 标签 | 可选，多个标签用“、”或逗号隔开，比如 `免费、新增` |
| 置顶 | 可选，填“是”进入首页热门推荐 |
| 分类说明 | 可选，写在该分类的任意一行，显示在分类标题下面 |

注意：
- 表格读取失败（网络不通、链接错了）时，页面会自动改用 `sites.js` 里的本地数据，所以本地数据建议保留一份。
- 表格发布后，更新通常有几分钟延迟。
- Google 表格在中国大陆可能需要特殊网络才能访问，访问者那边读不到时同样会退回本地数据。如果你的主要读者在国内，建议继续用 `sites.js`，或者把表格定期导出覆盖。
- “发布到网络”意味着任何人拿到链接都能看到表格内容，不要放不想公开的东西。

## 检查

- **格式**：改完 `sites.js` 后打开页面，如果提示“站点数据 sites.js 没有加载成功”，多半是对象里漏了逗号或引号，或者末尾的分号被删掉了。
- **重复和失效**：每月随手点开几个，打不开的就删掉。不需要任何脚本。

## 部署

整个目录是纯静态文件，三个文件放在同一个目录，双击 `index.html` 就能在本机打开，放到 GitHub Pages、Cloudflare Pages 或任意静态服务器即可。用 GitHub 的话，可以直接在网页或手机 App 里编辑 `sites.js`，保存后网站自动更新，并保留每次修改记录。
